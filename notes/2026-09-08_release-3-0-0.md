# 2026-09-08 — Cutting 3.0.0

The release commit for BWOC 3.0. Everything the four release gates check moves
together here, because they are designed to go red if it does not:
`release_pointers.rs` ties `Cargo.toml`, `README.md`, `VERSION.md` and
`Formula/bwoc.rb` to the topmost `CHANGELOG.md` entry, and
`whats_new::highlights_cite_current_version` fails unless a bullet names the
current MAJOR.MINOR.

## What changed

- `scripts/bump-version.sh major --software` → **3.0.0**; `minor --document` →
  1.14.0 (two new spec docs plus rewrites across ROADMAP / RELEASING / VERSION).
- `CHANGELOG.md` — the `v2026.9.8-0 — 3.0.0` entry, with a Migration section.
- `README.md` / `VERSION.md` "Latest release" lines repointed.
- `whats_new.rs` — new tagline, a 3.0 bullet at the top, and the oldest bullet
  (2.38.0 gated financial writes) dropped to stay inside the six-bullet cap.
- **All 29 in-tree plugin manifests re-declared** `compat = ">=3.0.0, <4.0.0"`,
  plus the ~29 inline fixtures in `check.rs` and the per-resolver test modules,
  and `modules/plugin-template/SPEC.md`.

## Decisions

- **The plugin sweep belongs in this commit, not the one that added enforcement.**
  A bounded `>=3.0.0, <4.0.0` does not match 2.44.x, so sweeping the manifests
  before the version bump would have made every plugin refuse to load on every
  intermediate `main`. Enforcement landed first against the old unbounded
  ranges (which matched), and the ranges tighten here, in the same commit as
  the version they refer to.
- **`Formula/bwoc.rb` stays at the previous release.** Its checksums only exist
  after the artifacts do, which is why `the_homebrew_formula_is_at_most_one_release_behind`
  tolerates exactly one release of lag. `release.yml`'s `bump-formula` job opens
  the bump branch once the tag is pushed.
- **`util::tests::compat_matches_inside_the_declared_range` keeps a `">=2.7.0"`
  against `"2.44.2"` case.** Both are literals, so it does not go stale — and it
  is the test that documents *why* the convention changed: the old shape matched
  a version two majors away.

## Verified against the real fleet

The 12-agent workspace at `~/workspaces/bwoc` is the regression suite. The 3.0.0
binary reads it unmigrated (12 agents listed, no errors — dual-read holds), and
`bwoc migrate --all --dry-run` plans 25 rewrites.

It also reports **one genuine pre-existing defect**: `agent-caretaker/AGENTS.md`
is hand-written and has no `| **Version** |` row at all, so `migrate` refuses it
and says why rather than guessing at the edit. That is the intended behaviour —
the file needs a human, and the run tells the operator which one. Worth fixing
in the fleet separately; it is not a framework bug.

## Status / deferred

The tag itself (`git tag v2026.9.8-0 && git push origin v2026.9.8-0`) is the
remaining step, and it is deliberately a human one — pushing the tag triggers
`release.yml`, which builds and publishes artifacts.
