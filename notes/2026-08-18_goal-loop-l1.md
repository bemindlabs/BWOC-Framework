# 2026-08-18 — Goal loop L1 (loop-engineering, first slice)

The first implementation slice of the [loop-engineering layer](../docs/en/LOOP-ENGINEERING.en.md):
a **goal + ticker loop** around the already-hardened Saṅgha lead drain. Chosen as
L1 because it validates the whole `Goal + Ticker + Gate` shape on the most-tested
primitive (`run_lead`) with the least net-new code.

## What changed

- **`crates/bwoc-harness/src/lead.rs`** — new `run_goal_loop`: re-fires `run_lead`
  until one terminal condition holds:
  - **Goal / DoD** — every task in the source is `Completed`.
  - **Gate / blocked (HELD)** — a fire claimed nothing but work remains
    (dependency-blocked, or a task awaits plan approval). The loop stops rather
    than spin, and the message names whether it's a HELD plan-approval case.
  - **Budget** — a hard `max_iterations` ceiling so an unattended loop provably
    halts even if DoD is never reached.
  - **Ticker** — a fixed `interval` sleep between fires (L1; cron/adaptive is L2).
  The DoD/HELD decision is a pure `evaluate_goal(tasks, claimed) -> GoalStatus`
  so it's unit-testable without spawning workers or git worktrees.
- **`crates/bwoc-harness/src/main.rs`** — `--loop` (requires `--lead`) switches
  lead mode from a single drain to the goal loop; `--loop-interval-secs`
  (default 5) and `--loop-max-iters` (default 20) tune the ticker + budget. The
  outcome (Done / blocked / budget-exhausted) is printed with accumulated counts.

## Decisions
- **`evaluate_goal` is pure** — the gate logic is separated from the async
  drain/worktree machinery so it tests cheaply and exhaustively (all-done,
  in-progress, dependency-blocked, plan-approval HELD).
- **Blocked, not budget, is the primary stop** for a stuck list — a fire that
  claims nothing while work remains means no self-progress is possible; halting
  immediately (with a reason) beats burning the whole budget spinning.
- **Budget defaults to a finite 20**, not unbounded — an unattended loop must
  halt by default (the spec's no-autopilot rule); `0` opts into unbounded.

## Alternatives considered
- Requiring N consecutive no-progress fires before Blocked (rejected: `run_lead`
  awaits all workers before returning, so a single claimed==0 fire already means
  nothing is claimable — no transient to smooth over).
- Full cron/adaptive ticker now (deferred to L2 per the build plan — L1 is the
  minimal validating slice, Mattaññutā).

## Status / deferred
- **L2** — `Cron`/`Every`/`Adaptive` ticker on the daemon idle loop; the
  fleet-health-remediation and Tier-2-mining loops.
- **L3** — product loops (monitoring/alerting flagship), the middle trust tier,
  idempotency/dedup.
- ROADMAP ticketing of the L-phases is a follow-up (this PR ships L1 code only).
