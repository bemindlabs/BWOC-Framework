# 2026-09-19 — Release 3.3.0 (`v2026.9.19-0`)

Minor release on top of 3.2.0.

## What shipped
- **Runtime R4a** (#532): several conversations per directory — `bwoc --new`, `bwoc --session <id>`, `bwoc session list`, `bwoc session fork` and `bwoc session rm`; 3.2 conversations migrate on first open, keeping their id.
- **Bare `bwoc` on vendor coding CLIs** (#529 → #530): `--backend claude|codex|agy|kimi|grok|copilot` execs that CLI on its own login; `[defaults] backend` stands in for `[runtime] backend`.
- **Chat TUI controls** (#531): `Ctrl-C` is the only exit, `↑/↓` scroll, `←/→` edit, a controls footer, no idle repaint (native copy works).

## Decisions
- **Minor, not patch:** `### Added` (R4a).
- **Scope cut from the plan (user's call, 2026-09-19):** the runtime plan had 3.3 = R4–R5. 3.3.0 ships R4a only; R4b (undo/redo), R4c (protocol Cancel/SetModel/diff/cost) and R5 (TUI: in-TUI session switching/fork via slash commands, Markdown rendering) move to 3.4. The small chat-pane control refinements (#531) shipped independently.

## Known residuals
- No in-TUI session switching or fork (R5 slash commands).
- Markdown is still not rendered in the TUI (R5).

## Rollout (2026-09-20)
- **Release PR #533** was blocked by 7 unresolved Copilot threads, not CI. Fixed 6 (copy-safe `bwoc session list` / `fork` / `rm` instead of a pipe-looking `list | fork | rm`; named the deferred R5 items); answered 1 as by-design (Document-Version has held at 1.14.0 across the 3.x release PRs).
- Tag `v2026.9.19-0` → `release.yml` green (5 targets + formula branch). Formula PR #534 opened by hand (Actions can't open PRs); sha256 checked against the published sidecars.
- **Second review before the fleet push** (grok, operator's call): 3.3.0 cleared to ship — no session collision across several conversations per directory, and the 3.2 → 3.3 migration holds. One medium UX finding: after `session fork`, bare `bwoc` resumes the fork while the message implied the original → reworded in #536.
- **Rollback caveat:** the 3.2 → 3.3 migration is a `rename`. A binary downgraded to 3.2 after 3.3 opened a directory starts a fresh conversation (file intact under `<dir-hash>/`). The autoupdate smoke (`--version`, `doctor --json`, `list`) opens no session, so its automatic rollback is unaffected.
- The nightly `bwoc-autoupdate.timer` would have pushed `main` to the fleet mid-review; stopped by the operator, then `bwoc-autoupdate.sh` run by hand: all 3 hosts `bwoc` + `bwoc-harness` 3.2.0 → 3.3.0, smoke green, `doctor` 0 fail.
